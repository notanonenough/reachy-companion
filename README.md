# Reachy Companion

Автономный компаньон Reachy Mini: робот захватывает звук и выполняет движения,
Raspberry Pi Hub ведёт цикл решений и координирует работу, Mac выполняет
распознавание, генерацию речи и моделей, Xiaomi/OpenWrt связывает устройства.

Репозиторий содержит исходники и воспроизводимую конфигурацию четырёх узлов.
Каноническое описание установки — **[`deploy/current/`](deploy/current/manifest.json)**.
Локальные `config.*.local.json`, секреты, модели, память и журналы не коммитятся.
Версии моделей и программ закреплены в manifest/lock-файлах; шаблоны конфигурации
содержат ссылки на отдельно предоставляемые секреты.

Актуальная версия проекта находится в ветке **main**. От неё начинаются новые рабочие ветки. Решения по развитию и правила приёмки изменений собраны в [блокноте проекта](docs/REVIEW-NOTES.md).

## Управление установленной системой

На настроенном Mac:

```sh
scripts/production-control status --json
scripts/reachy-on
scripts/production-control stop
scripts/reachy-off
```

`start` создаёт новый автономный сеанс. `stop` закрывает сеанс и оставляет модели
загруженными. `reachy-off` выключает также вычислительные процессы Mac.
После STOP или утраты полномочий автоматического повторного старта нет.

Панель: [http://127.0.0.1:18080/control](http://127.0.0.1:18080/control).
Она управляет микрофоном, громкостью, режимом разговора, самостоятельными вопросами,
доступом к камере и разрешением на движение. Вход требует ключа из `secrets/token`.
Разрешения камеры/движения сами не запускают автономный сеанс. Камера — доступ
компаньона к кадрам; отключение питания камеры или аппаратный STOP этим не заявляются.

## Разработка и проверки

Python 3.13, Node.js 22+ для теста панели. Нужен полный Git checkout: часть
регрессионных тестов сравнивает код с историческими коммитами.

```sh
python3.13 -m venv .venv-review
.venv-review/bin/python -m pip install -r requirements/dev.lock -r requirements/robot.lock
.venv-review/bin/python -m pip install --no-deps -e .
.venv-review/bin/python -m unittest discover -s tests
node tests/test_conversation_mode_page.cjs
.venv-review/bin/python -m build --no-isolation
```

Проверки устройства не заменяют тесты: `scripts/production-control status` и
`deploy/current/release.py verify` показывают состояние установки и совпадение
файлов. Физическую речь, слежение и движения проверяют отдельно, при явно
запущенном сеансе.

## Организация кода

- `src/reachy_companion/` — Agent, Hub, router, worker, панель и общие компоненты.
- `src/reachy_companion/autonomous/` — планировщик, состояние, адаптеры и шлюз моделей.
- `deploy/current/` — единственная каноническая конфигурация текущей установки.
- `deploy/autonomous/production_start.py`, `device_audio_runtime.py`, `observer_service.py` — действующие точки запуска.
- `scripts/` — команды оператора, диагностика и инструменты других поддерживаемых платформ.
- `tests/` — регрессии; исторические preimage/patch данные нужны только для тестов.
- `native/`, `worker/`, `deploy/workflows/` — альтернативные подсистемы; в текущей схеме они не запущены.

Изменение запуска/сети сначала вносится в шаблоны `deploy/current/`, затем
проверяется рендерингом и устанавливается с резервной копией. После изменения
шаблона обновляется его SHA-256 в manifest. Запуск старых одноразовых миграций
не является способом установки текущей системы.
